# Project packages — Phase 6

The optional Module Framework installs modules per project. `Engine::install_module(source_dll, id, dependencies, error)` validates a local DLL through Plugin ABI v1, checks its reported module ID, copies it into `<project>/Modules/<id>/<DLL filename>`, and registers that relative path for the current `Engine`. The DLL is never installed into a shared directory. The operation is unavailable while modules are active.

IDs use ASCII letters, digits, `.`, `_`, and `-`; `.` and `..` alone are rejected. The source must be a regular `.dll` file. Existing destinations and staging directories are not replaced. Installation copies into a staging directory below the project's `Modules/` and renames that directory only after the copy succeeds. A copy failure removes the staged file and directory. The registry also rejects a `Modules/` directory redirected outside the project.

Installation writes `<project>/Modules.lock` using a versioned text format. Each entry records module ID, relative DLL path, enabled state, optional package version, dependency IDs, and SHA-256 of the installed DLL. The current format is `ATMERA_LOCK 3`; it also records one previous path, version, and hash when an update has occurred. Version 1 and 2 lockfiles remain readable and are rewritten as version 3 on the next change. Both LF and CRLF line endings are accepted. The lockfile is first written to `Modules.lock.partial` and then replaced atomically; if the commit fails, the newly installed DLL and registration are rolled back. A new `Engine` can call `load_installed_modules(error)` before registering or starting modules. It validates all entries and installed DLL hashes before accepting any of them. Installing through a new `Engine` automatically loads an existing lockfile before adding the module, so earlier entries are preserved.

`Engine::install_module_versioned(source_dll, id, dependencies, version, error)` requires a numeric `major.minor.patch` version, with up to 64 characters. `Engine::module_version(id)` returns that value after installation or reload. The original `install_module` API continues to install unversioned modules and stores an empty version. The version is caller-provided metadata; Plugin ABI v1 does not report or authenticate package versions.

`Engine::set_module_enabled(id, enabled, error)` changes a registered module while it is stopped. A fresh Engine loads an existing lockfile automatically before changing a flag. The dependency resolver checks the proposed configuration: disabling a module still required by an enabled module fails, so dependents must be disabled first; enabling them again follows dependency order. A successful change updates `Modules.lock`. If writing the lockfile fails, the prior enabled flag remains in memory and on disk. A repeated request for the current value succeeds without rewriting the file.

`Engine::update_module_versioned(source_dll, id, version, error)` replaces the selected module while the Engine is stopped. It requires a different numeric version and a local DLL whose Plugin ABI module ID matches. The new DLL is staged below `<project>/Modules/<id>/` and committed as `<project>/Modules/<id>/<version>/<DLL filename>`. The prior DLL remains in the project. The lockfile points to the new version and hash and keeps one previous version record. If copying or committing the lockfile fails, the new version directory and in-memory path/version are rolled back; the old lockfile and DLL stay usable. The method does not initialize the updated plugin. Normal `start(error)` reports a later initialization failure without changing the selected version.

`Engine::rollback_module(id, error)` runs while the Engine is stopped. It verifies the retained DLL against its recorded hash, then swaps the current and previous paths/versions in the lockfile. Calling it again selects the other version. A failed lockfile commit leaves the current selection unchanged. Only one previous version is recorded; a further update replaces that rollback slot.

`Engine::start_with_rollback(error, rolled_back_id)` starts the enabled modules. If a plugin fails during initialization and has a retained previous version, it stops initialized modules, verifies and selects that previous version, persists the selection, then retries startup once. On recovery it returns `true` and writes the reverted module ID to `rolled_back_id`. If the retry fails, it returns `false` and keeps the reverted version selected; `rolled_back_id` still identifies the reverted module. If no previous version exists, or startup fails for another reason, it returns the original failure and leaves `rolled_back_id` empty. A lockfile write failure preserves the current selection and reports both the startup and rollback errors. Only the failed module is reverted; no further automatic retries occur.

The hash detects changes relative to the lockfile; it is not a publisher signature. The lockfile does not contain external download information. Consumers can still use `add_module` for DLLs already present in the project.

# RHI specification

The RHI is part of the independent ATMERA graphics library. Neither the Module Framework nor Studio project manifests are prerequisites for its basic use. Phase 3.5 retains the v1 HWND rendering route and adds a null-HWND route for offscreen work. Both backends keep presentation state separate from device/queue/resource state internally. The null-HWND renderer can create resources, record offscreen lists, submit, wait, and read texture pixels; frame presentation, resize, and swapchain center-pixel calls require an HWND-backed renderer.

## Implemented Phase 2 slice

`SDK/Include/ATMERA/RenderABI.h` defines a versioned C table shared by the independent `ATMERA.D3D11.dll` and `ATMERA.D3D12.dll`. The caller loads a backend by explicit DLL path, obtains `atmera_get_render_api`, checks ABI version and table size, then creates an opaque renderer with either a Win32 HWND or a null window handle. Both backends expose capability query, resize, frame rendering, optional swapchain center-pixel readback, GPU buffer and texture operations, and destruction. The samples switch backends without changing draw calls. `GraphicsContext.hpp` is the C++ RAII loader/renderer owner.

The public table compiles vertex/pixel shaders, creates a graphics pipeline, and records a frame through `begin_frame`, `bind_pipeline`, `draw`, and `end_frame`. `end_frame` submits and presents. Only one frame may be open per renderer, and transfers must happen outside a frame. Shader and pipeline handles belong to their renderer; the pipeline must remain alive through submission. The basic `create_pipeline` path has no vertex input layout and suits `SV_VertexID` geometry. The clear color and render target format are fixed for this baseline. `render_frame` remains a convenience path; the triangle sample uses the explicit commands.

Texture views and samplers are exposed. The basic binding set pairs one RGBA8 shader resource at `t0` with one point or linear sampler at `s0`, using clamp or wrap addressing. The set, its view and sampler, and the underlying texture belong to the creating renderer. The set must remain alive through frame submission; independent list resources stay alive through its fence wait. D3D12 transitions sampled textures from `COMMON` to `PIXEL_SHADER_RESOURCE` for the draw and back to `COMMON` before submission completes. The smoke test verifies textured pixels and reads the texture again after both frame and independent-list draws.

`get_graphics_queue` returns the renderer's non-owning graphics queue handle. `create_command_list` creates an independent list that can record one or more buffer copies; `submit_command_list` consumes it once and returns a fence. Wait on the fence before destroying it or its source/destination buffers. A submitted list can be destroyed before the wait because the fence retains its GPU dependencies. D3D11 implements this with a deferred context, compiled command list, and event query. D3D12 uses a separate command allocator/list, explicit `COMMON`/copy transitions, queue signal, and fence event. This is a single-threaded baseline with one queue per renderer.

`command_copy_texture` copies a full single-mip RGBA8 image between two distinct textures of the same dimensions. It records outside a render-target pass. Both textures must belong to the command list's renderer and remain alive until the returned fence completes. D3D12 transitions each texture from `COMMON` to its copy state and back; D3D11 records `CopyResource`. The smoke test checks exact pixel bytes after a fence wait and rejects self-copy and mismatched dimensions.

`command_copy_texture_region` copies a rectangular pixel region between distinct RGBA8 textures, including textures with different overall dimensions. Source and destination rectangles must both fit, and width and height must be nonzero. It also records outside a render-target pass. D3D11 uses `CopySubresourceRegion`; D3D12 uses `CopyTextureRegion` with explicit copy-state transitions. The smoke test checks copied and untouched pixels, multiple regions in one list, and invalid bounds.

Independent lists also support offscreen drawing into a renderer-owned RGBA8 texture: `command_begin_render_target`, `command_bind_pipeline`, `command_draw`, and `command_end_render_target`. A target pass must be ended before queue submission; drawing requires a bound pipeline. The target begins with the same fixed clear color as a swap-chain frame. D3D12 transitions the target from `COMMON` to `RENDER_TARGET` and back. Wait on the returned fence before reading or destroying the target. The sample checks the rendered center pixel through `read_texture` on both backends. Swap-chain presentation still uses `begin_frame`/`end_frame`; these independent lists do not present.

`command_bind_binding_set` binds the existing fixed `t0`/`s0` texture and sampler pair during an independent offscreen pass. The sampled texture must differ from the active render target. D3D12 retains descriptor heaps and texture resources through fence completion and transitions the sampled texture into the pixel-shader state and back. The smoke test checks the textured target pixel, source texture contents, and rejection of binding the target as its own source.

`bind_constant_buffer` and `command_bind_constant_buffer` expose one renderer-owned constant buffer at `b0` to vertex and pixel shaders during a frame or independent offscreen pass. The buffer must have constant usage and a 256-byte-aligned size; writes remain whole-buffer operations. D3D11 binds the buffer to VS and PS slot 0. D3D12 uses a root CBV and transitions the resource from `COMMON` to the vertex/constant state and back. The smoke test uses a tint constant to change the triangle color in both paths and reads the buffer after drawing.

An explicit binding-layout slice can select a texture register `t0`–`t15`, one sampler register `s0`–`s15`, and one constant-buffer register `b0`–`b13`. `create_binding_layout` returns a renderer-owned layout; `create_pipeline_with_binding_layout` creates a pipeline for `SV_VertexID` geometry, and `create_binding_set_with_layout` pairs a view and sampler using the layout's registers. Pipelines and sets copy the register values, so the layout handle may be destroyed after creation. Binding a set with registers that differ from the current pipeline is rejected. D3D11 binds at the selected slots; D3D12 creates a matching root signature for the pipeline. The smoke test uses `t2/s3/b4` in a frame and an independent list and verifies the sampled and tinted pixel.

`create_pipeline_with_texture_pair` and `create_binding_set_with_texture_pair` extend that layout to two distinct RGBA8 textures at consecutive `tN` and `t(N+1)` registers, sharing one sampler and one constant-buffer register. The base texture register must be at most `t14`. A one-texture set cannot bind to a pair pipeline. D3D12 allocates two adjacent SRV descriptors and tracks both textures through frame or independent-list submission. The sample blends two textures, checks frame and offscreen pixels on both backends, and rejects duplicate texture views. Arbitrary resource arrays and multiple binding groups remain future work.

`create_pipeline_with_texture_sampler_pair` and `create_binding_set_with_texture_sampler_pair` use the same two texture slots with independent samplers at consecutive `sN` and `s(N+1)` registers; both base registers must be at most 14. D3D12 copies two sampler descriptors into one shader-visible heap. A shared-sampler pair set cannot bind to this pipeline. The sample reads a patterned texture at its center with point and linear sampling and checks their different colors in frames and an independent offscreen list on both backends.

`create_pipeline_with_vertex_layout` accepts up to 16 named vertex attributes, each with a semantic index, byte offset, and `FLOAT1`, `FLOAT2`, `FLOAT3`, `FLOAT4`, packed `UNORM8X4`, or `HALF2` format. `HALF2` maps to `R16G16_FLOAT` and occupies four bytes. This layout uses one interleaved vertex stream at slot 0. During an offscreen target pass, `command_bind_vertex_buffer` binds a renderer-owned vertex buffer with stride and offset; `bind_vertex_buffer` does the same during a swap-chain frame. The stride must cover every declared attribute, and draw rejects a vertex count beyond the bound buffer. D3D12 transitions the buffer into the vertex state for the pass or frame and returns it to `COMMON` afterward. The sample now draws its visible triangle from vertex data. The smoke test checks both offscreen and swap-chain pixels, plus packed-color and scalar-intensity offscreen pixels, on D3D11 and D3D12.

`create_pipeline_with_two_vertex_streams` accepts separate slot 0 and slot 1 attribute layouts, with at most 16 attributes in total. `bind_vertex_buffer_slot1` and `command_bind_vertex_buffer_slot1` bind the second buffer during a frame or offscreen pass. Both slots validate stride and non-indexed draw bounds. D3D12 tracks each buffer's state and retains command-list buffer resources until its fence completes; the two slots currently require distinct buffers. The sample sends position through slot 0 and packed color through slot 1 and checks offscreen and swap-chain pixels on both backends.

The sample draws `HALF2` positions with packed RGBA8 colors through both a single interleaved stream and two separate streams. `HALF4` adds an eight-byte `R16G16B16A16_FLOAT` attribute; the sample pairs it with `HALF2` positions in both stream layouts, rejects an undersized interleaved stride, and checks offscreen and swap-chain center pixels on D3D11/D3D12 with WARP and hardware. The new format constant is additive to Render ABI v1; the table layout is unchanged.

`UNORM16X2` adds a four-byte `R16G16_UNORM` vertex attribute for compressed UV coordinates. The sample uses UV values 0 and 65535 to select different texels, checking an interleaved offscreen draw, a two-stream offscreen draw, and a swap-chain frame on both backends. It rejects undersized vertex strides. This format constant also extends ABI v1 without changing its table layout.

`UNORM8X2` adds a two-byte `R8G8_UNORM` vertex attribute. UV components 0 and 255 select the left and right texels in the sample. A single interleaved stream is checked in an offscreen draw, and slot 2 of a three-stream pipeline is checked in a swap-chain frame. Both paths reject strides below their declared attribute size. The format value extends ABI v1 without changing the table layout.

`create_pipeline_with_three_vertex_streams` takes separate layouts for slots 0, 1, and 2, with 16 attributes maximum across them. `bind_vertex_buffer_slot2` and `command_bind_vertex_buffer_slot2` bind the third stream in a frame or offscreen pass. Draw validates all required streams and their strides. D3D12 requires distinct buffers in all three slots and returns each to `COMMON` after the pass or frame. The C table appends these three functions after the existing ABI v1 prefix; callers check `struct_size` before using them. The sample supplies position, packed color, and compressed UV in separate buffers, rejects a missing slot 2 and short stride, and checks red/green sampled pixels in offscreen and swap-chain draws on both backends.

Index buffers now support `ATMERA_INDEX_UINT16` and `ATMERA_INDEX_UINT32`. `bind_index_buffer`/`draw_indexed` work during a swap-chain frame, and `command_bind_index_buffer`/`command_draw_indexed` work during an offscreen command-list pass. Bindings require an index-usage buffer, an aligned offset, and enough bytes for the requested index count; vertex indices in the buffer must refer to valid vertices. D3D12 transitions the index buffer into `INDEX_BUFFER` state and back to `COMMON`. The smoke test checks 16-bit offscreen and 32-bit swap-chain drawing, including missing bindings and counts beyond the buffer.

The buffer API creates vertex, index, or constant buffers (one usage per buffer) and supports full or partial writes and reads. Constant buffers require 256-byte size alignment and whole-buffer writes for cross-backend compatibility. The texture API currently supports single-mip RGBA8 2D textures with full-image writes and reads; caller row pitch may include padding. Resource handles belong to the creating renderer and backend table and must be destroyed before the renderer. Transfers are synchronous for this baseline. The sample validates data round trips and resource recreation before and after swap-chain resize on WARP and hardware.

D3D11 uses implicit resource state management, D3DCompile/DXBC Shader Model 5, a swap chain, a render target view, and a staging texture for test readback. D3D12 uses explicit present/render/copy transitions, DXC/DXIL Shader Model 6, command queue/list/allocators, a root signature and pipeline, fences, and a readback buffer. The sample selects hardware by default and retries WARP on initialization failure. The hidden smoke path forces WARP, renders before and after resize, and verifies a triangle-colored GPU pixel.

The D3D12 sample waits for the GPU every frame to make resource lifetimes simple and deterministic. This is intentionally a correctness baseline; asynchronous frames are future work. Both backends passed WARP and hardware pixel readback on the development machine. The hardware reported D3D11 feature level 11.0 and D3D12 feature level 12.2 / Shader Model 6.6.

## General RHI still to implement

The current C table is a rendering slice rather than the final general RHI. The planned public interfaces are `IDevice`, `ICommandList`, `ICommandQueue`, `IBuffer`, `ITexture`, `ITextureView`, `ISampler`, `IShaderModule`, `IPipeline`, `IBindingLayout`, `IBindingSet`, `ISwapChain`, and `IFence`. Buffer/texture resources, views, samplers, shader/pipeline creation, one- and two-texture binding layouts, basic vertex and index input, draw/submit commands, and independent buffer/texture copy and offscreen draw command lists with queue/fence synchronization are exposed. General resource arrays, more vertex formats and slots, swap-chain drawing on independent lists, and multiple queue types remain to be made public. D3D11's implicit behavior and D3D12's explicit behavior will stay visible where needed rather than being artificially hidden.

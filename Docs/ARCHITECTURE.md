# Architecture

ATMERA is an independent modular graphics library. The optional Module Framework contains the current DirectX-independent Kernel runtime. Studio is a separate WPF SDK consumer for graphics development and verification. A future game engine is a separate consumer, outside this repository's product scope. Graphics must not require Studio, the Module Framework, or project manifests. See [product boundaries](PRODUCT_BOUNDARIES.md) and [migration plan](MIGRATION_PLAN.md).

`ATMERA.sln` builds `ATMERA.ModuleFramework`, `ATMERA.Graphics`, the D3D11/D3D12 backends, two test plugin DLLs, `ATMERA.KernelTests`, Triangle and external-consumer samples, and the independent Studio executable with Visual Studio 2022. Graphics and backends do not link Module Framework. Each `Engine` owns a logger, service registry, event bus, and module registry bound to one project directory. The registry resolves dependencies, validates enabled DLL paths under that project's `Modules/`, and initializes plugins in order; failure unwinds them in reverse order. The loader removes services and subscriptions before unloading each DLL. `Engine` remains the compatible name for this module-only facade.

The Rendering slice builds `ATMERA.D3D11.dll` and `ATMERA.D3D12.dll` as independent backends behind `RenderABI.h`. The Triangle sample loads one backend at runtime and passes the same HLSL source to either. D3D11 compiles Shader Model 5 DXBC; D3D12 uses DXC for Shader Model 6 DXIL. Studio loads backend DLLs through the public C ABI and does not link their internals. `ATMERA.Graphics` exposes a C++ RAII owner for DLL and renderer lifetime. Both backends create device/queue state without an HWND and attach presentation state only for the window path. The external-consumer sample validates both paths through public headers, with no Studio or project manager.

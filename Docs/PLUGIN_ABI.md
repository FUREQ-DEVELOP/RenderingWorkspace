# Plugin ABI v1

This ABI belongs to the optional Module Framework, which is independent of rendering and WPF. Basic ATMERA graphics calls use `RenderABI.h` and do not require a plugin host. Phase 3.5 preserves Plugin ABI v1 while separating the products.

The authoritative declarations are in `SDK/Include/ATMERA/PluginABI.h`. A DLL exports `atmera_get_plugin_api`. The host passes ABI version 1 and receives a DLL-owned function table with `struct_size`, `abi_version`, `module_id`, `initialize`, and `shutdown`. The host validates the table before calling it. `initialize` receives a size/version checked host table and returns an opaque handle; `shutdown` consumes it. The host owns the DLL and must call `shutdown` before `FreeLibrary`. Strings and function tables are valid only while the DLL remains loaded. A nonzero return means failure. Neither side may pass STL objects or C++ exceptions across this boundary.

The host table has append-only v1 fields for service registration/lookup and event subscribe/unsubscribe/publish. A plugin must check `struct_size` before accessing an extension. IDs, event names, messages, and payloads are NUL-terminated UTF-8 strings; callback payload pointers are valid only during the call. Service pointers are borrowed and may be used only while their owning module remains active. The host context remains valid through `shutdown`. Event callbacks run synchronously on the publishing thread. The loader removes each module's services and subscriptions during unload, before `FreeLibrary`. The registry and event bus are currently single-threaded and should be accessed from the engine thread.

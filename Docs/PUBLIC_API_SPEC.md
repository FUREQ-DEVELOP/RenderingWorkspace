# Public graphics API boundary

`SDK/Include/ATMERA/RenderABI.h` is the stable C ABI v1 boundary implemented by both backend DLLs. Its structures use fixed-width fields, sizes, opaque handles, and function pointers. Backends export `atmera_get_render_api`; consumers pass `ATMERA_RENDER_ABI_VERSION` and check the returned table size, version, and functions before use. Phase 3.5 did not change the table layout or ABI version.

`SDK/Include/ATMERA/GraphicsContext.hpp` is the minimal C++ RAII entry point. `ATMERA.Graphics.lib` implements it without linking either backend, Studio, or the Module Framework. `GraphicsContext::open` loads the backend DLL by explicit path, validates ABI v1, creates one renderer, and returns an owning context. Its destructor calls `destroy(renderer)` before unloading the DLL. A failed load or create returns an empty pointer and fills the error string. The caller owns the context and must destroy all renderer-owned buffers, textures, shaders, pipelines, command lists, and fences first. A submitted command list's resources must stay alive until its fence is waited. The queue handle is borrowed and must not be destroyed. A non-null HWND is borrowed and must remain valid until the renderer is destroyed.

`SDK/Include/ATMERA/RenderGraph.hpp` provides a separate C++ planning API for explicit pass dependencies, inferred read/write ordering, stable scheduling, resource-use intervals, and graph-owned temporary RGBA8 texture and buffer declarations. It is implemented in `ATMERA.Graphics.lib`, independent of the backend DLLs. A cyclic graph returns an empty optional. Resource lifetime steps refer to positions in the scheduled order. See [Render Graph](RENDER_GRAPH.md).

`SDK/Include/ATMERA/RenderGraphExecutor.hpp` provides a C++ helper that executes a graph serially on a `GraphicsContext`. Its callback can access graph-owned texture and buffer handles by resource ID. The executor creates them at first use, destroys them after the last pass fence, and owns each temporary command list and fence. The caller retains ownership of resources declared with `add_resource()`. It reports failure as `false`; the existing Render ABI v1 table is unchanged.

`SDK/Include/ATMERA/BloomBrightPass.hpp`, `BloomDownsamplePass.hpp`, `BloomBlurPass.hpp`, and `BloomCompositePass.hpp` provide optional Phase 5 extraction, linear downsampling, 3×3 Gaussian blur, and original-image composition passes. Each compiles and owns its pipeline using only the public Render ABI. The caller owns source/target textures and keeps each pass object alive through fence completion. They are implemented in the separately linked `ATMERA.Bloom.lib` and add no C ABI members. See [Bloom](BLOOM.md).

The optional `get_shader_reflection` pointer is appended to Render ABI v1. Callers check `atmera_render_api.struct_size` before reading it, provide a live opaque shader handle, and initialize `atmera_shader_reflection.struct_size`. The backend copies the shader stage and counts of compiled constant-buffer, texture, and sampler binding declarations into the caller-owned fixed-width struct. Unused HLSL declarations may be omitted by the compiler. Existing ABI v1 table members retain their offsets; older DLLs without this extension remain loadable by prefix-aware clients.

The subsequent optional `get_shader_bindings` pointer reports those binding declarations in detail. Call with a null buffer and zero capacity to query `required_count`, then allocate that many `atmera_shader_binding` entries and initialize every `struct_size`. Each record contains kind, register index, register space (zero on D3D11), and register count for arrays. The caller owns the buffer; insufficient capacity and undersized records are rejected. Check the API table size before reading the appended pointer.

The appended `get_shader_binding_name` pointer returns the compiled HLSL name for a binding index in the same order as `get_shader_bindings`. Query `required_bytes` (including NUL) with a null output buffer and zero capacity, then provide a caller-owned UTF-8 buffer. An unknown index or insufficient capacity fails without writing the output. Check the table size before reading this optional pointer; older ABI v1 backends do not provide it.

The appended `get_shader_cache_stats` pointer copies renderer-local `create_shader` hit, miss, and entry counts into caller-owned `atmera_shader_cache_stats` after its `struct_size` is initialized. Each backend keeps at most one exact source/entry match per vertex and pixel stage. Built-in renderer creation is excluded from these counters. Cache replacement does not invalidate existing shader handles; cached data is released with the renderer. The cache is in memory only and does not cross renderer or project boundaries.

`atmera_render_desc.window_handle` may be null. In that case the backend creates a device and graphics queue without a swapchain; resource creation, copy commands, offscreen render-target commands, fence wait, and texture readback work. `begin_frame`, `render_frame`, `resize`, and `get_center_pixel` require a window-backed renderer and fail for a headless renderer. Non-null HWND preserves the original v1 presentation path. Width, height, and HLSL source are still required by v1 creation in both modes; a more granular device creation API would require a later additive ABI extension.

The backend implementation types and DirectX headers remain private in `Rendering/D3D11` and `Rendering/D3D12`. Module Framework C++ declarations and `PluginABI.h` remain public for consumers that opt into module loading; they are not needed for graphics. The implementation-only `PluginLoader.hpp` moved from `SDK/Include/ATMERA/` to `Engine/PluginRuntime/`; direct includes of that former SDK path must be replaced with the supported `Engine.hpp`/`ModuleRegistry.hpp` APIs. This is a C++ source-include migration only: Plugin ABI v1 is unchanged. Studio uses the public C table via P/Invoke. No C++ exceptions, STL types, or ownership of caller memory cross either C ABI.

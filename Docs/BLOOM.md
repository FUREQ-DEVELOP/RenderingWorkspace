# Bloom — Phase 5

The separate `ATMERA.Bloom` static library exposes optional C++ `atmera::BloomBrightPass`, `atmera::BloomDownsamplePass`, `atmera::BloomBlurPass`, and `atmera::BloomCompositePass` helpers through their public SDK headers. Consumers link it explicitly alongside `ATMERA.Graphics`; the Graphics core does not link Bloom. The passes consume caller-owned RGBA8 textures and record offscreen work into a separate caller-owned RGBA8 target. They do not depend on Studio, the Module Framework, a project, or a particular backend DLL.

`BloomBrightPass::create(context, source, threshold)` accepts a finite threshold from 0 to 1. It creates the vertex/pixel shaders, pipeline, point sampler, source view and binding set, and a constant buffer. `record(command_list, target)` records a full-screen triangle. For each pixel, the shader keeps the sampled color when its largest RGB channel meets the threshold; otherwise it writes opaque black. The source and target should have the same dimensions. The caller owns both textures, the command list, and its fence. Keep the pass object and textures alive until the fence completes.

`BloomBlurPass::create(context, source, width, height)` takes the source dimensions and creates a fixed 3×3 Gaussian filter with point sampling and clamp addressing. The dimensions must match the source and target textures. Its `record(command_list, target)` method spreads RGB using weights 1:2:1 along each axis and writes opaque alpha. Zero dimensions are rejected. The caller keeps the pass and both textures alive through fence completion.

`BloomDownsamplePass::create(context, source)` uses linear sampling into a smaller target. A half-size target is the basic Bloom path; the caller creates both textures and provides a target with the desired dimensions. The pass writes opaque alpha. It also works as a general linear resampling pass, but its intended use here is downsampling.

`BloomCompositePass::create(context, original, blurred, intensity)` binds two distinct RGBA8 sources at t0/t1 and accepts a finite intensity from 0 to 1. `record(command_list, target)` writes opaque `saturate(original.rgb + blurred.rgb * intensity)`. It samples the original with a point sampler and the blurred texture with a linear sampler, so the blurred input may be smaller than the original and output. The original and output should have equal dimensions. The caller keeps the pass and textures alive through fence completion.

The four helpers form a basic Bloom chain: bright extraction at full resolution, downsampling, 3×3 blur at the smaller resolution, then composition at full resolution. A full-resolution three-pass chain is also supported. Multi-scale blur and tuning are future enhancements. The external consumer verifies the individual passes and both chains after GPU readback on D3D11 and D3D12 WARP in headless mode.

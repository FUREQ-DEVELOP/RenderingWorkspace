# Roadmap

ATMERA is an independent modular graphics library. The Module Framework is optional and graphics-independent; Studio and any future game engine are separate consumers. Phase 3.5 must finish before Phase 4 starts. See [product boundaries](PRODUCT_BOUNDARIES.md) and [migration plan](MIGRATION_PLAN.md).

- **Phase 0 — foundation: complete.** C++20 Core/Kernel, versioned C ABI, DLL loader, test plugin and lifecycle test, WPF shell, Visual Studio solution, baseline documentation. `ATMERA.sln` built in Debug|x64 and Release|x64 with Visual Studio 2022; `Tools/Test.ps1` passed in both configurations on Windows 11 x64.
- **Phase 1 — runtime: complete.** Project-bound module registry, service registry, event bus, dependency resolver, lifecycle rollback, two interacting test plugins. `ATMERA.sln` and `Tools/Test.ps1` passed in Debug|x64 and Release|x64.
- **Phase 2 — RHI: in progress.** Independent D3D11/D3D12 DLLs, capability query, shared HLSL triangle, resize, WARP fallback, GPU pixel readback, public buffer/texture transfers, shader/pipeline creation, swap-chain frame commands, texture views, selectable t/s/b registers with one or two textures and one or two samplers per binding set, FLOAT1–4, HALF2, HALF4, packed RGBA8, UNORM16X2, and UNORM8X2 vertex input across one, two, or three streams, and independent buffer/texture copy and offscreen draw command lists with queue/fence synchronization are working. A dedicated D3D12 sample project and solution launch profile allow F5 visual inspection. Both backends passed Debug/Release WARP tests and Release hardware smoke tests including compressed-UV texture sampling. Remaining: general resource arrays and binding groups, additional vertex formats and stream slots, swap-chain drawing on independent lists, and multiple queue types.
- **Phase 3 — Studio: minimal graphics debugger.** Rebuilt Studio around one embedded viewport. It switches D3D11/D3D12, optionally forces WARP, opens or reloads a local HLSL shader, restores the bundled shader, pauses and steps frames, and shows renderer capabilities and compiler errors. Project creation, Assets browsing/editing, Inspector previews, and external preview launching were removed from Studio. Debug|x64 `ATMERA.sln` and `Tools/Test.ps1` passed after the rebuild: the hidden Studio smoke path covered first render, pause/step, HLSL failure and recovery on both backends, bundled reset, forced WARP, backend switch, and resize. Release build/test and manual visual inspection of the rebuilt UI have not been run.
- **Phase 3.5 — Architecture Separation: complete for the current Phase 2/3 slice.** `ATMERA.ModuleFramework` and `ATMERA.Graphics` are separate native targets; D3D11/D3D12 DLLs remain independent, and Studio is a public ABI consumer. A C++ RAII context loads and owns a backend DLL and renderer. Both backends create a device without HWND for offscreen rendering and keep the original window path; presentation state is separate from device/queue/resource state. The external C++ sample uses public headers only and passed window/headless GPU pixel checks on both backends with WARP and hardware. Debug/Release `.sln` builds and `Tools/Test.ps1` passed; direct Release build of the external consumer target did not build Studio or Module Framework. The current verified Phase 2/3 slice is the migration boundary; remaining RHI and Studio work stays on its phase backlog.
- **Phase 4 — shader/render graph: complete for the current command ABI.** The Graphics SDK provides a backend-independent C++ `RenderGraph` for explicit dependencies, deterministic scheduling, cycle detection, access inference, initialization checks, and resource lifetimes. Its serial executor manages temporary RGBA8 textures and vertex/index/constant buffers by use interval. D3D11/D3D12 expose compiled shader binding counts, register details, UTF-8 binding names, and a bounded per-renderer shader cache through append-only C ABI v1 functions. Debug|x64 `ATMERA.sln` and `Tools/Test.ps1` passed across graph, GPU, shader, native, and Studio regressions. D3D12 commands record their own state transitions, so a graph barrier API is deferred until a command requires it. Broader cache policy and metadata remain demand-driven. Release build/test were not run for these slices.
- **Phase 5 — graphics modules: complete for basic Bloom.** The separately linked `ATMERA.Bloom` target provides public C++ helpers for threshold-based bright extraction, linear downsampling, fixed 3×3 Gaussian blur, and intensity-scaled composition. Graphics, Studio, and the Module Framework do not depend on Bloom. D3D11/D3D12 headless WARP tests verify individual passes, a full-resolution three-pass chain, and a half-resolution four-pass Render Graph chain; Debug|x64 `ATMERA.sln` and `Tools/Test.ps1` passed. Multi-scale blur and tuning remain optional enhancements. Studio remains a minimal graphics debugger. Release build/test were not run for these slices.
- **Phase 6 — project package management: complete for local packages.** The optional Module Framework validates a local plugin DLL and its ABI/module ID, stages it under one project's `Modules/`, and registers it. Project-local `Modules.lock` v3 persists IDs, paths, enabled flags, optional numeric versions, dependencies, SHA-256 hashes, and one previous version; v1/v2 files remain readable. Enable/disable changes check dependencies and persist atomically. Versioned replacement retains the old DLL. Explicit rollback verifies and swaps to it while stopped; opt-in startup rollback handles one plugin initialization failure by selecting the retained version and retrying once. Kernel tests verify project isolation, old lockfile compatibility, hash mismatch, dependency-safe toggles, replacement, explicit and automatic rollback, persisted recovery, and failed-write recovery; Debug|x64 `ATMERA.sln` and `Tools/Test.ps1` passed. Release build/test were not run for these slices.
- **Phase 7 — online repository: in progress.** `RenderingWorkspace` holds modifiable source and the Visual Studio development environment; `RenderingLibrary` is reserved for completed SDK distribution and release assets, without buildable source. GitHub CLI development tools search published module releases and download a DLL with a SHA-256 sidecar into one project's `Downloads/` directory. The new `ATMERA.ModuleTool` solution target installs or updates the verified DLL through the Module Framework, which checks its Plugin ABI ID and persists it only in that project. Debug|x64 `ATMERA.sln` and `Tools/Test.ps1` passed, including offline search/download, hash-mismatch cleanup, install, update, and ABI mismatch rejection. A live search with `fureq-dev` returned the current empty catalog. Remaining: a real release download check and public runtime repository API. Release build/test were not run for this slice.
- **Phase 8 — public SDK/distribution:** external templates and graphics runtime packaging.
- **Phase 9 — advanced rendering:** further graphics capabilities. Game-engine functionality is excluded from ATMERA.
